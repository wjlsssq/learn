# ADR 0003：订单事实存储与可靠事件

- 日期：2026-11-13
- 状态：已采纳，实现待用户验证

用户基于 Redis、锁、线程池和 MQ 问答提出完整订单学习场景，要求原生 MyBatis、详细后端注释与可读代码。采用独立 order-lab 模块，复用门户导航与公共 HTTP/Web 能力，资源按工程隔离。

库存只在 MySQL 中维护，使用商品行锁和条件 UPDATE；不为了展示 Redis 而引入两套库存事实及尚未实现的对账。Redis 用于短 Lua 限流和 Redisson 订单协调锁，锁失效时仍由数据库状态约束兜底。

订单支付与 Outbox 同事务，异步发送采用数据库租约、有界线程池和 Confirm/Return；消费者事务提交后 ACK，以消费记录和业务唯一键约束重复效果。选择本地事务加至少一次投递，不声称跨 MySQL/MQ/Redis 的全局事务或绝对不丢消息。

单商品、模拟支付、同库积分适合当前学习链路；真实支付、多 SKU、跨库积分和高可用部署需要后续独立设计。可靠性机制已经实现，运行、故障、容量与生产验收尚未完成。详细边界和恢复路径见 projects/order-lab/docs/DESIGN.md。
