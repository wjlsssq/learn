# ADR 0001：采用单仓多工程与手动接入规范

- 日期：2026-11-12
- 状态：已采纳

## 背景

项目用于个人逐步学习 Java、Agent、Redis、MQ 等知识。希望保留清晰的前端、后端和数据边界，复用必要基础能力，通过一个文件夹式门户进入各工程。学习工程可能使用 Python 或混合技术栈，内部结构尚处于探索中。

## 决策

采用统一仓库、多独立工程、少量公共能力和门户导航的组织方式。前端由 pnpm workspace 管理，Java 模块由 Maven 聚合管理；其他语言保持适合自身的构建与依赖方式。

首阶段建立 Vue 门户、Java 基础服务、必要 Web 机制和文档体系。门户工程清单静态维护，开发进程通过命令启动。无需账号体系，当前不引入业务数据库或中间件。

新增工程按学习目标设计，遵循接入指南；当前不开发工程生成器。重复稳定的局部操作可以在未来单独评估自动化。

## 取舍与影响

- 同仓便于同步维护规范、公共模块和文档；需要持续约束工程依赖，目录本身不能代替边界。
- 每个工程可以独立运行、采用不同技术栈；也需自行声明依赖、启动命令和验证方式。
- 公共能力逐步形成，减少对尚未出现的需求作假设；公共接口变更仍需验证消费者。
- 手动接入保留设计空间；依靠接入清单和检查保证一致性，等重复步骤稳定后再考虑局部脚本。
- 运行状态来自实际探测，页面仅提供导航与状态展示；本地进程生命周期由终端管理。

## 复审条件

当出现多个工程的稳定重复需求、真实跨工程通信、集中运行管理或公开部署需求时，针对对应问题新增决策，不自动扩大当前基础设施范围。
