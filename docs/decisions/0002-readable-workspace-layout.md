# ADR 0002：提高可读性并重新组织主区域布局

- 日期：2026-11-12
- 状态：已采纳；实现效果待用户验证

## 背景

用户反馈工作台文字偏小，核心内容区存在较多空白。静态阅读样式后，可以看到多个说明、标签和命令采用约 9–12px 的字号及较浅颜色；列表固定列数和大型接入提示也不能随真实工程数量调整。仅扩大容器或增加卡片高度，不能同时改善阅读和空间利用。

本次目标是让学习内容更容易阅读，并通过真实信息的分组、对齐和换列利用主区域。保留已有完整工程页、左侧菜单、顶部面包屑与真实运行状态，不新增业务功能、虚构进度或尚未接入的工程。

## 官方资料及采用范围

- [GOV.UK Paragraphs](https://design-system.service.gov.uk/styles/paragraphs/) 将正文和较小正文区分为 19px 与 16px，并建议较小正文节制使用。[GOV.UK Type scale](https://design-system.service.gov.uk/styles/type-scale/) 使用字号和行高层级，并以相对单位输出。这里借鉴层级和缩放方式，具体字号按本项目的任务界面与中文阅读需要选择，不复制其字体或品牌样式。
- [IBM Carbon Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview) 区分任务型产品界面和表达型内容的排版策略。[Carbon 2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview) 使用一致的间距节奏，并根据任务决定扩展列数还是扩大内容块。这里借鉴信息层级、8px 节奏和内容驱动的栅格组织，不照搬整套设计系统。
- [W3C WCAG 2.2：Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 说明普通文字至少 4.5:1、大字至少 3:1 的对比度要求。[Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) 说明纵向阅读内容在等效 320 CSSpx 宽度下的重排目标，并允许确需二维布局的内容例外。这里将其作为设计和用户验收目标，未声称本次已通过可访问性认证。
- [MDN：Common grid layouts](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Common_grid_layouts) 展示按断点切换一至三列等栅格组织方法。这里用响应式重排控制信息密度，保持文档顺序和导航关系，不使用视觉填充代替真实内容。

## 决策

### 统一字号与颜色角色

公共令牌由 `shared/frontend/ui/src/tokens.css` 维护。字号采用 `rem`，其值相对于浏览器根字号；以下像素说明按默认根字号 16px 换算。

| 角色 | 选择 |
| --- | --- |
| 辅助信息和代码 | 0.875rem，约 14px |
| 导航和操作 | 约 14–16px |
| 常规正文 | 1rem，约 16px；行高 1.65 |
| 连续阅读正文 | 1.125rem，约 18px |
| 面板标题 | 1.25rem，约 20px |
| 页面标题 | 2rem，约 32px；手机约 28px |

主要文字、次要文字、辅助文字和品牌操作分别使用 `#18263e`、`#42516a`、`#59677d`、`#254cc5`。用字号、字重和分组区分层级，辅助文字也保持可读的深浅程度。字号和颜色是本项目设计选择，不是 WCAG 指定的样式值；最终对比度需针对实际背景与交互状态核对。

### 收敛间距并按真实内容布局

间距以 8px 为主要节奏，常用 8 / 16 / 24 / 32px，细节采用 4 / 12px。主区域使用完整可用宽度，内边距采用 `clamp(1rem, 1.5vw, 1.75rem)`，在默认根字号下约 16–28px，减少原先过大的顶部及两侧空白。侧栏宽 16rem，在 56rem 及以下视口收起。保留内容间必要的阅读间距和对齐关系，不通过压缩正文行高提高密度。

工程列表根据当前筛选结果数量分配列数：一个结果使用单列横向信息卡，两个结果使用两列，三个及以上最多三列；80rem 及以下视口最多两列，48rem 及以下单列并恢复纵向信息卡。`single-project` 与 `two-projects` 类由实际结果数量产生，不按预期的未来工程数量预留空槽。工程接入指南放入普通操作行，移除大型占位卡片。信息不足时保持真实，不增加假工程、假进度或无意义数据。

工程页组织为三个独立内容组：操作组为入口和命令，学习组为能力和学习目标，参考组为运行状态、源码位置和文档。视口达到 90rem 时三列；56rem 至 90rem 之间两列，操作与学习依次放在左侧，参考信息位于右侧；56rem 及以下按操作、学习、参考顺序排列为一列。面板按真实内容自然增高，不强制拉到相同高度。缩窄窗口优先换列，不继续缩小正文和辅助文字。

长地址、路径和命令须保持完整可读：一般文本可换行，必要的代码横向滚动限制在代码区域。组件参数、事件、Hash 导航和数据归属保持原有契约，布局变更不触发后端请求或进程启动。

## 取舍

- 较大的正文会增加局部内容高度，通过重排和减少过大容器间距平衡，而非把文字重新压小。
- 主区域宽度服务于多个内容组；文档页使用约 18px 正文，文档面板最长 92ch，控制连续长文的行长，不要求每一段文字铺满整屏。
- 共享令牌会影响列表、工程和文档页，需要由用户关注这些实际消费者的阅读与交互表现。
- 列数和断点属于当前布局实现，后续新增工程或更长中文内容时，应结合真实内容调整，不依赖固定高度占位。
